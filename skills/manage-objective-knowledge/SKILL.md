# 目的と知見の管理

目的を保ち、現在の理解とその根拠を更新する。
フォルダ構成と最小テンプレートは [workspace.md](../../references/workspace.md) を読む。

## 目的を選ぶ

- 利用先の `AGENTS.md`、指定された保存先、既存の目的フォルダを確認する。分析環境、実行コマンド、データアクセス、保存・共有の制約は利用先の規則に従う。このskillだけを理由に環境を導入したり `AGENTS.md` を変更したりしない。
- 対象の目的が決まっているなら、その `DESCRIPTION.md`、`CURRENT_STATE.md`、`KNOWLEDGE_INDEX.md` を読み、必要な知見と分析記録だけを辿る。
- 新規作成が依頼された、または分析の実行に必要なら、利用先に目的フォルダを作る。保存先が未指定なら `objectives/<目的のslug>/` を使う。pluginの配布ディレクトリに利用者の記録を置かない。
- 判断・理解したい目的が変わったら別フォルダを作る。同じ目的の仮説、手法、期間の変更は追加の記録として扱う。
- `DESCRIPTION.md` は初期に目的を定義し、通常の進捗更新では変更しない。表現の訂正や目的を変えない明示的な補足は反映してよい。目的変更をこのファイルの書き換えで隠さない。
- 目的の選択で分析が変わる場合だけ確認する。検索・相談だけなら保存せず、整理案を返す。

## 経験と知見を残す

- 実行した分析、意味のある比較、判断、失敗、否定結果を `analyses/<記録ID>/record.md` に残す。分析の実行は [$analyze-objective](../analyze-objective/SKILL.md) の手順を使う。同じ試行の記録を重複作成しない。
- 「問い→方法と選んだ理由→観測結果→解釈→限界→次の判断」を短くつなぐ。実際に確認したコード、表、図、資料への参照を主張の近くに置く。
- 未実行の提案を結果にしない。作業や議論だけなら、その判断と根拠、未実行の検証を記録する。定型的な完了ログや会話全文は蓄積しない。
- 再利用する知見を `knowledge/<分類>/<知見のslug>.md` にまとめる。使う場面、条件、判断手順、理由、限界、元の記録への参照を含める。
- 単一の試行から広い原則を断定しない。暫定の知見でも条件と未検証範囲を明記して残せる。支持が増えたら根拠を追加し、矛盾や反例は条件差とともに残す。
- 類似する知見は既存ファイルへ新しい根拠・条件を統合する。分類は必要になってから作り、深い階層を先に設計しない。

## 別の目的から取り込む

- 別目的の検索・取り込みは明示された依頼の範囲で行う。通常の分析では現在の目的だけを使い、自動で他の目的や私的な保管場所まで探索しない。
- 指定範囲の `DESCRIPTION.md` と `KNOWLEDGE_INDEX.md` から候補を絞り、本文と必要な根拠を読む。アクセス不能と該当なしを区別する。
- 今回の目的・データ・期間・前提と照合し、使える部分だけを現在の目的の知見として記録する。元の目的と知見への参照、参照日、適用理由、未検証の条件を付ける。
- 取り込んだ知見は今回の目的で未検証と明記する。今回の試行で検証したら、その根拠を追加する。元の現在地や履歴を丸ごと複製しない。
- 元の記録は変更しない。参照先にアクセスできなければ根拠を検証したと言わない。

## 現在地と索引を更新する

1. 分析・作業の記録と、必要な個別知見を先に確定する。
2. `CURRENT_STATE.md` を現在の結論、根拠、未解決事項、次の確認に更新する。新しい知見がなくても現在地が変われば更新する。古い結論を現行の結論として残さず、変更理由は元の記録に残す。
3. 個別知見を追加・変更・取り込みしたら `KNOWLEDGE_INDEX.md` の要約、適用条件、状態、リンクを更新する。新しい根拠がない場合は不要な更新をしない。
4. 変更したファイルを読み戻し、相対リンクと根拠、現在地と索引の整合を確認する。実行済み・未実行・判断不能を区別して報告する。

機密データや資格情報は知見や作業記録へ転記しない。保存制約や書き込み不能がある場合は内容を回答内に返し、保存済みとは言わない。
