# 目的フォルダの契約

利用先の既存構成を優先する。未指定なら `objectives/<目的のslug>/` に保存する。
plugin自体には手順だけを置き、実際の知見や分析記録は利用先へ保存する。

| 目的フォルダからの相対パス | 内容・更新時点 |
|---|---|
| `knowledge/DESCRIPTION.md` | 目的の定義。作成時に記入し、通常の進捗では更新しない |
| `knowledge/CURRENT_STATE.md` | 現在の結論と未解決事項。現在地が変わったら更新 |
| `knowledge/KNOWLEDGE_INDEX.md` | 知見の索引。個別知見を追加・変更したら更新 |
| `knowledge/<分類>/<知見のslug>.md` | 条件と根拠を伴う知見。分類は必要なときだけ作る |
| `analyses/<記録ID>/record.md` | 一回の分析・意味のある作業の問い、方法、結果、根拠 |
| `analyses/<記録ID>/` 内のコード・図等 | 利用先の保存規則に従う、記録の根拠になる成果物 |

記録IDは `001-roc-comparison` のような未使用の連番と短い名前にする。
同じ目的の追加分析は同じ目的フォルダに新しい記録を作る。
現在地は複数記録を統合した答え、知見は条件付きで使える判断手順とする。
分析ごとの全文を管理ファイルへ重複掲載しない。

## 初期化テンプレート

以下は最小の構成。括弧内を実際の内容で置き換え、該当しない項目は削除してよい。
未確認・未実行はそのまま明記し、空欄を結果で埋めたことにしない。

### knowledge/DESCRIPTION.md

```markdown
# 目的

(判断・理解したいこと)

## 背景
(なぜ必要か)

## 対象・範囲
(母集団・対象期間など。具体的な実行条件は各分析記録に置く)

## 完了の目安
(何がわかれば目的を満たすか)
```

### knowledge/CURRENT_STATE.md

```markdown
# 現在地

更新日: YYYY-MM-DD

## 現在の結論
まだ分析していない。

## 根拠
なし。

## 未解決事項
(未確認の問い)

## 次の確認
(次に行う最小の比較・検証)
```

### knowledge/KNOWLEDGE_INDEX.md

```markdown
# 知見の索引

更新日: YYYY-MM-DD

| 知見 | 要点・役立つ問い | 適用条件 | 状態 |
|---|---|---|---|
```

知見欄には個別ファイルへのリンクを置く。状態は「暫定」「条件内で確認」
「取り込み・今回未検証」「反例あり」など、実態に合う短い表現でよい。
確認した根拠の範囲を超えて「確認済み」にしない。

## 個別知見のテンプレート

```markdown
# (知見のタイトル)

状態: (根拠の強さ・未検証範囲)
更新日: YYYY-MM-DD

## 使う場面と条件
(どんな問い・データ・条件に使うか)

## 判断・手順
(入力、比較方法、読み方、終了条件)

## 理由と根拠
(観測事実と解釈を分け、元の分析記録へリンク)

## 限界・反例
(適用できない場面、矛盾、追加検証)
```

別目的から取り込む場合は「参照元」「参照日」「今回に適用する理由」と
「今回未検証の条件」を追記する。元の知見を今回の実験結果として扱わない。

## 分析・作業記録のテンプレート

```markdown
# (記録のタイトル)

日付: YYYY-MM-DD
状態: 計画 / 実行済み / 判断不能 / 中止 / 作業記録

## 問い・判断
(今回何を知りたいか。計画時の評価・終了条件)

## 方法と選んだ理由
(比較、入力の識別子・所在・期間、単位、指標・分母、条件、主要パラメータ)
(コードへのリンク、実行方法・環境の識別情報、重要な仮定や計画との差)

## 観測結果と根拠
(実際の数値・表・図・確認内容へのリンク。未実行ならそう明記)

## 解釈・限界
(言えること、言えないこと、失敗・否定結果)

## 次の判断
(採用・回避・追加検証。関連する以前の記録があればリンク)
```

実行済みは試行の成功を意味しない。評価できる否定結果も含む。
判断不能は試したが問いに答えられない状態、中止は評価前に止めた状態とする。
議論や作業だけの場合は未実行の検証を観測結果と分けて記載する。

リンクは記載ファイルからの相対パスにする。例えば `knowledge/CURRENT_STATE.md`
から最初の記録へは `../analyses/001-roc-comparison/record.md`、分類配下の知見からは
`../../analyses/001-roc-comparison/record.md` とする。保存後に実在を確認する。
